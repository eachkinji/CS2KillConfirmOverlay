## 创作约定

- 称呼按用户最新偏好：成品使用“玩机器”“玩出”“6657”等直播间原生称呼，或自然省略主语，避免泛称“主播”。此前“不写玩机器本人”的限制已撤销。原始 `source_excerpt` 保持原文，不能为了更换称呼伪造来源；改写后不再保留的 `classic_anchor` 应清空。

- 成功事件也以嘲讽主播、嘴硬、甩锅运气和拆台为主；反话捧杀必须在句内能读出讽刺，不加入真实赞美来平衡情绪。
- 优先选择原库有辨识度、能自然用于该事件的经典表达。摘录至少四个字符，记录原文的一基索引及具体改写说明。不用单字关联掩盖无关来源，不靠相同前缀和尾句排列组合凑数。
- `classic_anchor` 记录成品保留的连续原句片段，至少四个字符，同时出现在成品与该条原文中。深度改写可留空；每池至少 35% 保留此类片段，其他条目允许借原梗结构创新。这个比例衡量文本保留，不代表经典热度排名或审美质量，不能用通用四字短语凑指标。
- 每池 100 条，单行、最长 30 个 UTF-16 字符，检查精确去重及 NFKC 去标点、空白、emoji、变体选择符后的去重。至少 30 个源条，同一源条最多选 5 条。另行审查近义模板、来源牵强和上下文错配。
- 至少 70% 文案带 emoji，让 emoji 参与表情、括号小剧场、嘴硬与反转。避免所有句尾贴同一个表情，也不把换 emoji 当作新文案。保留无 emoji 的短促复读，如用户指定的“运”。
- 独立内容复审重点查真夸、反串没有拆台、拗口硬贴原文、机械同义改写与事件事实错配。作者自报“全部通过”不能代替复审；审查结果需经主 agent 核对后应用。
- 每个 worker 只写自己的候选文件，主 agent 等待完整任务结果后接入正式池。候选文件生成不等于任务成功，也不等于已经更新应用。
- `intent`、`family`、`phase`、`classic_anchor`、`derivation_note` 供编辑审查；当前运行时并不按这些字段选择文本，仍然在对应事件池内随机抽取并排除近期 64 条相同文本。
